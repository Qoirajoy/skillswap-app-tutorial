Next steps and troubleshooting

The first version is a campus bulletin board that works. This page is your desk reference: how to change SkillSwap, what to add next, and what to do when something breaks.

5.1 Making changes to SkillSwap

You do not rebuild from scratch every time. You describe the next slice, test it on your computer, then publish.

  1. Change it in Cursor. Open your skillswap project and tell Agent what you want.
  2. Test locally. Run npm run dev and check http://localhost:3000.
  3. Push to GitHub. Use Cursor’s source control panel or ask Agent to push.
  4. Wait for Vercel. It detects the push and redeploys in a couple of minutes.
npm run dev

5.2 Ideas for features to add

Stay inside the bootcamp fence: no file uploads, no chat, no payments, no extra email, no AI matching. These additions still make SkillSwap feel more finished:

  • Edit or delete your posts. Maya should be able to update “presentation due next week” when the date changes.
  • Mark a request resolved. Close a post when you already found help so Discover stays useful.
  • Filter matches by college. Sometimes you want someone in your school; sometimes you want anyone on campus.
  • An interests inbox. A simple list of people who expressed interest in you, with accept and decline.

Talk to Cursor the way you would brief a teammate:

“I want students to edit posts they created. Add an Edit button on My Posts that opens a form already filled with the title, skill, description, and status.”

5.3 Troubleshooting

Click a question to open it. Only one stays open at a time so the page stays calm.

Open the browser developer console: right-click the page → Inspect → Console. Look for red errors. Copy them and ask Cursor to fix the issue. A blank Discover page can also mean the app loaded but your tables are empty or Row Level Security is blocking reads.

Read the message — it often names a missing package or a typo. A common fix is to run npm install in the project folder, then try npm run dev again. If it still fails, paste the full error into Agent: “I’m getting this error when running npm run dev: [paste error]”

Check that NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY are set in the Vercel project. Read the build logs for red text. Confirm every file was pushed to GitHub. Add your Vercel URL in Supabase → Authentication → URL Configuration.

Confirm the Project URL and Publishable key. Use a real email you can open. Check spam for the 6-digit code. In Supabase, open Authentication → Users to see whether the account was created. If it works on localhost but not on the live site, the Site URL / Redirect URL is probably still set to localhost.

Did you push to GitHub? Open the repository and look at the latest commit. Vercel may need 1–2 minutes. Then hard-refresh the browser (Ctrl+Shift+R on Windows, Cmd+Shift+R on Mac) so you are not looking at an old cached page.

Open Supabase → Table Editor and see whether a row exists in posts. If the row is there but the site is empty, RLS is probably too strict (other students cannot select open posts). Ask Cursor to review the policies so logged-in users can read campus-wide posts and profiles, while still only editing their own.

Complementary matching needs two sides. On one account, offer Python and want presentation design. On another, offer presentation design and want Python. Skill names must match closely (avoid “Python 3” vs “python programming” in the first version). If both profiles look right in Table Editor, ask Cursor to walk through the match query with you.

You can delete the Vercel project and the GitHub repository, create a new skillswap folder, and run the build prompt again. That is a normal beginner move. Your Supabase project can stay; just keep using the same Project URL and Publishable key, or create a fresh project if the tables feel messy.
