Building SkillSwap

This is the fun page. You will open an empty folder, paste one carefully written prompt, and watch Cursor generate the app. You are still the product owner. The prompt is your spec sheet.

3.1 Create your project folder

Cursor works on whatever folder you open. An empty folder named for the product keeps files easy to find and keeps GitHub URLs clean.

  1. Create a new folder on your computer. Name it skillswap — no spaces, lowercase. Put it on your Desktop or in Documents.
  2. Open Cursor.
  3. Go to File → Open Folder and select that folder.
  4. The sidebar should look empty. That is correct.

Build me a Next.js web application. Here are the complete specifications:

## Tech Stack (DO NOT DEVIATE)
- Next.js with App Router (not Pages Router)
- TypeScript
- Tailwind CSS for styling
- Supabase for database and authentication (use @supabase/ssr and @supabase/supabase-js)

## Supabase Configuration
My Supabase Project URL is: YOUR_SUPABASE_URL_HERE
My Supabase Publishable key is: YOUR_SUPABASE_PUBLISHABLE_KEY_HERE

Store these in `.env.local` as:

NEXT_PUBLIC_SUPABASE_URL=YOUR_SUPABASE_URL_HERE
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_SUPABASE_PUBLISHABLE_KEY_HERE

Create a browser client at `src/lib/supabase/client.ts` and a server client at `src/lib/supabase/server.ts` using the official Next.js App Router pattern. Follow the Supabase Next.js quickstart linked above.

Use the installed Supabase plugin to create tables and Row Level Security policies. Do not ask me to paste SQL unless the plugin is not connected.

## App Description
SkillSwap is a university-wide platform that helps students find other students with the skills they need for academic, personal, or extracurricular tasks, while also giving them a place to offer their own skills. Every registered student can create a profile, list skills they can offer, list skills they want to learn, post help requests, post skill offers, and connect with other students. There are no separate helper and requester roles — a student can be both at the same time. Example: Maya (Business) needs presentation design and offers Python; Alex (Engineering) offers presentation design and needs Python. SkillSwap should surface that complementary match.

## Data Model
Create PostgreSQL tables in Supabase (use the installed Supabase plugin) with these entities:

- `profiles`: id (uuid, same as auth.users id), full_name (text), college (text), major (text), year (text), bio (text), created_at (timestamptz)
- `profile_skills`: id (uuid), user_id (uuid, references auth.users), skill_name (text), kind (text: "offer" | "want"), proficiency (text: "beginner" | "intermediate" | "advanced"), experience_notes (text), created_at (timestamptz)
- `posts`: id (uuid), user_id (uuid, references auth.users), post_type (text: "request" | "offer"), skill_name (text), title (text), description (text), status (text: "open" | "closed", default "open"), created_at (timestamptz)
- `interests`: id (uuid), from_user_id (uuid, references auth.users), to_user_id (uuid, references auth.users), post_id (uuid, nullable, references posts), message (text), status (text: "pending" | "accepted" | "declined", default "pending"), created_at (timestamptz)

And these relationships:
- Each profile belongs to one authenticated user
- Each user can have many profile_skills (offers and wants)
- Each user can create many posts (help requests and skill offers)
- Each interest is sent by one user to another user and may optionally point at a specific post
- Matching is computed in the app, not stored as its own table: find users who offer a skill you want and want a skill you offer

Enable Row Level Security on every table.
- Logged-in users can read all profiles, profile_skills, and open posts so campus-wide discovery works
- Users can insert, update, and delete only their own profile, skills, and posts
- Users can insert interests they send (from_user_id = auth.uid()) and read interests where they are the sender or the recipient
- Users cannot edit someone else's profile, posts, or incoming interests except to update the status of interests sent to them (accept / decline)

## Authentication
Implement user authentication using Supabase email one-time codes (OTP):
1. User enters their email
2. Supabase sends a 6-digit code to that email
3. User enters the code to log in
4. Use `supabase.auth.getUser()` / `onAuthStateChange` to check login status
5. Protect routes that require authentication
6. After first login, if no profile row exists, prompt the student to complete college, major, year, bio, and at least one skill
7. Never use the secret (service_role) key in this app

## Pages to Create
- `/` - Discover: university-wide feed of help requests, skill offers, and students. Search by skill (e.g. Python, Excel, graphic design, public speaking). Filter by college. Login prompt if not authenticated
- `/login` - Login page with email input and 6-digit code verification
- `/profile` - The signed-in student's profile editor: name, college, major, year, bio, skills they can offer, skills they want to learn, proficiency, and relevant experience (requires auth)
- `/profile/[id]` - Public profile for another student
- `/posts/new` - Form to create a help request or a skill offer (requires auth)
- `/posts/[id]` - Post details with an Express Interest action
- `/matches` - Complementary SkillSwap suggestions based on offer/want overlap, with profile links and Express Interest (requires auth)
- `/my-posts` - Dashboard of the student's own requests and offers, including status (requires auth)

## Core Features
1. Students create and edit a profile with college, major, year, bio, and self-reported skills
2. Students add skills they can offer and skills they want, each with proficiency and optional experience notes
3. Students post help requests describing what they need and the useful skill
4. Students post skill offers describing what they can help with
5. Students discover people, requests, and offers by skill search and college filter
6. Students see potential matches when complementary needs and offers overlap (Maya needs Excel / offers Python; Alex needs Python / offers Excel)
7. Students express interest in helping or exchanging skills with another student
8. Students manage the status of their own posts (open / closed)

## UI Requirements
- Clean, modern, whimsy-professional design using Tailwind CSS: blush pink backgrounds, rose accents, pink skill pills, rounded cards
- Mobile-responsive (works on phones and desktops)
- Clear navigation between Discover, Matches, My Posts, Profile, and Login / Logout
- Loading states while data is being fetched
- Empty states (for example, "No matches yet — add a skill you can offer and a skill you want")
- Error messages when something goes wrong
- No file uploads, chat, payments, maps, AI matching, or email beyond the login code

3.4 What to expect

Cursor will start creating files in the sidebar. That can take a few minutes. Let it finish. It may ask clarifying questions — answer from your SkillSwap idea (university-wide, dual helper/requester, complementary matches, no chat).

Do not worry if:

  • Cursor asks you to run a terminal command. Read it, then let it run or paste it yourself.

3.5 Running SkillSwap on your computer

“Running locally” means previewing the restaurant in a private dining room before opening to campus.

  1. Open the terminal in Cursor (View → Terminal, or Ctrl+`)
  2. Type this command and press Enter:
npm run dev
  1. Wait until you see something like “Ready” and a URL
  2. Open your browser and go to http://localhost:3000
  3. You should see SkillSwap’s Discover page

What is localhost?

Your app is not on the internet yet. It is running only on this computer. localhost means “this machine.” :3000 is a port — think of it as a numbered door. Next.js stands behind door 3000 and serves SkillSwap to your browser.

Try the path a real student would take: open login, request a code, finish your profile, post one request and one offer, then check Matches. If the feed is empty, that is normal until you add data.

3.6 Fixing issues with Cursor

Errors are normal. They are also useful: they tell the AI exactly what broke.

  1. Look at the error in the browser or the terminal
  2. Copy the whole message
  3. Open Agent (Ctrl+I / Cmd+I)
  4. Paste it and say: “I’m getting this error. Please fix it.”
  5. Accept the suggested changes and try again

You do not need to decode the error yourself. You need to show it to the assistant. When the local app feels solid, you are ready to put SkillSwap on the internet.
