Put SkillSwap on the internet

Right now only your laptop can serve the app. Deployment moves SkillSwap onto a computer that stays on, so a classmate can open it from their phone at 11 p.m.

4.1 What is deployment?

If you close your laptop, localhost:3000 disappears. Deployment means putting the app on a server — a computer that is always on — so anyone with the URL can use it.

You will use Vercel because:

  • It is free for personal projects (Hobby plan)
  • It rebuilds automatically when you update GitHub
  • The same team built Next.js, so the two fit together

The path is: your computer → GitHub (the filing cabinet) → Vercel (the building). Students never visit GitHub to use the app. They visit the Vercel URL.

4.2 Push your code to GitHub

GitHub is not the live site. It is the official copy of your files. Vercel will pull from there.

  1. Go to github.com and sign in
  2. Click the + button → New repository
  3. Name it skillswap (lowercase, dashes if you need spaces)
  4. Keep it Public (needed for the simple free hosting path)
  5. Do not check README, .gitignore, or license — Cursor already created project files
  6. Click Create repository and leave that tab open

Now, in Cursor:

  1. Open the terminal (View → Terminal)
  2. Ask Agent: “Please help me push this project to GitHub. My repository URL is [paste the URL from GitHub]”
  3. Follow the git commands it suggests
  4. Refresh GitHub. You should see your SkillSwap files — not this tutorial folder, the app folder you opened in Section 3.1

Two different folders

This tutorial site (the pages you are reading) can live in its own GitHub repo for GitHub Pages. The SkillSwap Next.js app is a separate project. Deploy the app to Vercel. Host the tutorial on GitHub Pages if you want, using the README in this folder.

4.3 Deploy to Vercel

  1. Go to vercel.com and sign in with GitHub
  2. Click Add New Project
  3. Find and select your skillswap repository
  4. Before you deploy, add your Supabase credentials. Click Environment Variables and add both:
    • Name: NEXT_PUBLIC_SUPABASE_URL — Value: your Project URL
    • Name: NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY — Value: your Publishable key
  5. Click Deploy and wait 1–2 minutes
  6. When it says congratulations, click the URL. That is live SkillSwap.
NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-publishable-key-here

What are environment variables?

Some values should not be hardcoded in files that sit on a public GitHub repo. Environment variables pass those values into the app at build time.

The NEXT_PUBLIC_ prefix tells Next.js these two values are safe to expose to the browser. The Publishable key is public on purpose. Your real protection is Row Level Security, not hiding the address of the kitchen.

After the first deploy, open Supabase → Authentication → URL Configuration and add your Vercel URL (for example https://skillswap.vercel.app) as the Site URL and as a Redirect URL. Otherwise login emails will keep sending students back to localhost.

4.4 Your app is live

Congratulations. SkillSwap is on the internet. You can share the URL with friends, open it on your phone, and keep using it when your computer is off.

Automatic updates: whenever you push new code to GitHub, Vercel rebuilds. That usually takes one or two minutes.

A good first live test: create two accounts (you and a friend, or two email addresses). On one, offer Python and request presentation design. On the other, do the reverse. Confirm Matches shows the complementary pair, then express interest.
